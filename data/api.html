TinkLink-USB

Status Config System API

REST API Reference

All endpoints return JSON. POST endpoints take application/x-www-form-urlencoded parameters, except /api/config/restore (JSON body) and /api/ota/upload (multipart/form-data).

Successful POST responses include "status": "ok". Errors return an HTTP 4xx/5xx status with { "error": "..." }.

Status

GET /api/status

Get system status: WiFi, switcher, RetroTINK, AVR, and trigger mappings.

Response

{ "version": "1.12.0", "wifi": { "connected": true, "ssid": "MyNetwork", "ip": "192.168.1.100", "rssi": -65, "hostname": "tinklink", "state": "connected", "mode": "sta" }, "switcher": { "type": "Extron SW VGA", "currentInput": 1 }, "tink": { "connected": true, "powerState": "on", "lastCommand": "SVS NEW INPUT=1" }, "avr": { "type": "Denon X4300H", "enabled": true, "connected": true, "ip": "192.168.1.50", "input": "DVD", "lastCommand": "SIDVD", "lastResponse": "SIDVD" }, "triggers": [ { "input": 1, "profile": 1, "mode": "SVS", "name": "NES" } ] } // wifi.state: disconnected, connecting, connected, failed, ap_active // wifi.mode: sta, ap, ap_sta (ap_ssid and ap_ip are added while the access point is active) // tink.powerState: unknown, waking, booting, on, sleeping // avr: only { "enabled": false } when AVR control is disabled

WiFi

GET /api/wifi/scan

Scan for WiFi networks. The first call starts a scan and returns "status": "scanning"; poll until "status": "complete".

Response

{ "status": "complete", "networks": [ { "ssid": "MyNetwork", "rssi": -65, "secure": true }, { "ssid": "Guest", "rssi": -80, "secure": false } ] }
POST /api/wifi/connect

Connect to a WiFi network without saving the credentials. The device uses this network until it reboots, then returns to the saved network.

Parameters

NameTypeDescription
ssid string Network SSIDrequired
password string Network password (omit for open networks)

Response

{ "status": "ok" }
POST /api/wifi/disconnect

Disconnect from the current network. The device stays disconnected until it reboots or /api/wifi/connect is called, so you lose access if you're connected over WiFi. Has no effect in access point mode.

Response

{ "status": "ok" }
POST /api/wifi/save

Save WiFi credentials to flash for use on boot. Does not connect; call /api/wifi/connect as well to switch networks now.

Parameters

NameTypeDescription
ssid string Network SSIDrequired
password string Network password

Response

{ "status": "ok" }

Configuration

Changes made through these endpoints are saved to flash and take effect immediately, except /api/config/restore, which needs a reboot.

GET /api/config/triggers

Get trigger mappings (switcher input to RetroTINK profile).

Response

{ "triggers": [ { "input": 1, "profile": 1, "mode": "SVS", "name": "NES" }, { "input": 2, "profile": 2, "mode": "Remote", "name": "SNES" } ] }
POST /api/config/triggers

Replace all trigger mappings.

Parameters

NameTypeDescription
triggers string JSON array of trigger objects (the complete list)required

Trigger Object

FieldTypeDescription
input int Switcher input number (1 or higher)
profile int RetroTINK profile number (1 or higher)
mode string "SVS" sends SVS NEW INPUT=N; "Remote" sends remote profN. Anything else is treated as SVS.
name string Display name

Entries with an input or profile below 1 are dropped.

Response

{ "status": "ok" }
GET /api/config/tink

Get RetroTINK serial settings.

Response

{ "serialMode": "usb", "powerManagementMode": "full", "baudRate": 2000000, "defaultBaudRate": 2000000, "retroBridgeApi": true } // serialMode: usb or uart (set in config.json, applied at boot) // powerManagementMode: off, simple or full (set in config.json, applied at boot) // baudRate: current serial baud rate // defaultBaudRate: default for the serial mode (2000000 for usb, 115200 for uart) // retroBridgeApi: whether the Retro-Bridge compatible API (/api/v1/*) is enabled
POST /api/config/tink

Change RetroTINK settings. At least one parameter is required; changes apply immediately. Setting the serial mode's default baud rate removes the override from config.json.

Parameters

NameTypeDescription
baudRate int New baud rate
USB: 300, 600, 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200, 230400, 460800, 921600, 1000000, 1500000, 2000000, 3000000
UART: 300 to 5000000
retroBridgeApi bool Enable ("true") or disable ("false") the Retro-Bridge compatible API. Disabling it releases the serial link if an app is using it.

Response

{ "status": "ok", "baudRate": 115200, "retroBridgeApi": true }
GET /api/config/avr

Get AVR configuration.

Response

{ "type": "Denon X4300H", "enabled": true, "ip": "192.168.1.50", "input": "DVD" }
POST /api/config/avr

Update AVR configuration. Only the parameters provided are changed. Enabling or disabling creates or removes the AVR controller immediately.

Parameters

NameTypeDescription
enabled string "1" or "true" to enable; anything else disables
ip string AVR IP address (e.g., "192.168.1.50")
input string Denon input source (e.g., "GAME", "SAT/CBL", "DVD")

Response

{ "status": "ok" }
GET /api/config/backup

Download all device configuration (config.json and wifi.json, including the WiFi password) as one JSON object. A filesystem OTA update replaces both files, so back up first.

Response

{ "version": "1.1", "config": { "switcher": { "type": "Extron SW VGA", "uartId": 1, "txPin": 43, "rxPin": 44, "autoSwitch": true }, "tink": { "serialMode": "usb", "powerManagementMode": "full", ... }, "hardware": { "ledPin": 21, "ledColorOrder": "RGB" }, "avr": { "type": "Denon X4300H", "enabled": true, "ip": "192.168.1.50", "input": "DVD" }, "hostname": "tinklink", "triggers": [ ... ] }, "wifi": { "ssid": "MyNetwork", "password": "...", "hostname": "tinklink" } } // version: backup format (MAJOR.MINOR), separate from the firmware version
POST /api/config/restore

Restore configuration from a backup. Overwrites config.json and wifi.json with the sections present in the backup. Reboot afterwards to apply. Backups with a newer major format version are rejected.

Request Body

Content-Type: application/json, the JSON object returned by /api/config/backup.

Response

{ "status": "ok", "message": "Config restored. Reboot to apply." }

RetroTINK

POST /api/tink/send

Send a raw command to the RetroTINK 4K over the configured serial connection (USB or UART), framed as \r<command>\r. Replies from the RetroTINK (e.g. [COM] Serial Remote: prof1) appear in the system log. Returns ok even if the RetroTINK isn't connected; the command is then only logged.

Parameters

NameTypeDescription
command string Command to send (e.g., "remote prof1", "SVS NEW INPUT=1", "pwr on")required

Response

{ "status": "ok", "command": "remote prof1" }
POST /api/tink/trigger

Run the trigger mapped to a switcher input, exactly as if the switcher had just selected that input: the RetroTINK is woken if it is asleep, and the profile command is sent once it is ready. The switcher itself and the AVR are not touched. Handy for testing trigger mappings. Returns 404 if no trigger is mapped to the input.

Parameters

NameTypeDescription
input int Switcher input number (1-based)required

Response

{ "status": "ok", "input": 1 }
ANY /api/v1/*

Retro-Bridge compatible API. Lets apps written for the Retro-Bridge WiFi adapter — the RT4K Profiler and Remote web apps — connect to TinkLink by address and talk to the RetroTINK through TinkLink's serial link. In the app, choose Connect via Retro-Bridge and enter this device's IP address or .local hostname.

TinkLink only relays bytes between the app and the RetroTINK. One app operation uses the serial link at a time; while one is in progress, TinkLink's own commands (input triggers, /api/tink/send) are held back and sent as soon as the link is free. These endpoints are the only ones that send CORS and Private Network Access headers, since the apps are public web pages. This API is meant for those apps rather than for scripting — use /api/tink/send for that. Disable it with retroBridgeApi under Configuration.

AVR

AVR configuration is under Configuration. These endpoints return 400 while AVR control is disabled.

GET /api/avr/discover

Discover Denon/Marantz AVR receivers on the local network via SSDP (UPnP multicast on port 1900). The first call starts discovery and returns "status": "discovering"; poll until "status": "complete".

Response

{ "status": "complete", "devices": [ { "ip": "192.168.1.50", "name": "Denon AVR-X4300H" } ] }
POST /api/avr/send

Send a raw command to the Denon AVR via telnet (TCP port 23). A CR terminator is added automatically. If the command can't be sent, returns 500 with "status": "error".

Parameters

NameTypeDescription
command string Denon protocol command (e.g., "PWON", "SIGAME", "PW?", "SI?")required

Response

{ "status": "ok", "command": "PWON" }

Common Denon Commands

CommandDescription
PWONPower on
PWSTANDBYPower standby
PW?Query power state
SIinputSelect input (e.g., SIGAME, SISAT/CBL)
SI?Query current input
MVnnSet volume (e.g., MV50)
MV?Query volume

Switcher

POST /api/switcher/send

Send a message to the video switcher over its serial port (9600 baud for the Extron SW VGA). CR+LF is appended automatically.

Parameters

NameTypeDescription
message string Message to send (e.g., "1!" selects input 1 on an Extron)required

Response

{ "status": "ok", "message": "1!" }
GET /api/switcher/receive

Get recent messages received from the video switcher.

Parameters

NameTypeDescription
count int Max messages to return (1-50, default: 10)
clear any If present, clear the message buffer before reading

Response

{ "count": 2, "messages": [ "In1 All", "In2 All" ] }

Debug

POST /api/debug/led

Set the status LED color. The LED returns to WiFi status indication after 10 seconds.

Parameters

Use one of these options:

NameTypeDescription
color string Named color: red, green, blue, yellow, cyan, magenta, white, off
r, g, b int RGB values (0-255 each, all three required)
reset any Return the LED to WiFi status indication now

Response

{ "status": "ok", "r": 255, "g": 0, "b": 0 } // reset returns only { "status": "ok" }

Logs

GET /api/logs

Get system log entries. The device keeps the last 100 entries. Use since for incremental polling.

Parameters

NameTypeDescription
count int Max entries to return (1-100, default: 50)
since int Return only entries logged after this index (use total from the previous response)
clear any If present, clear the log buffer

Response

{ "total": 42, "count": 2, "logs": [ { "ts": 3600, "lvl": 1, "msg": "WiFi: Connected!" }, { "ts": 3650, "lvl": 0, "msg": "Debug message" } ] } // total: number of entries logged since boot // lvl: 0=DEBUG, 1=INFO, 2=WARN, 3=ERROR // ts: milliseconds since boot

OTA Updates

GET /api/ota/status

Get current OTA update progress.

Response

{ "inProgress": false, "progress": 0, "total": 0, "percent": 0, "error": "" }
POST /api/ota/upload

Upload a firmware or filesystem image (multipart/form-data). The device reboots on success. A filesystem update replaces config.json and wifi.json; back up first (scripts/ota_upload.py backs up and restores automatically).

Parameters

NameTypeDescription
file file Binary image (.bin)required
mode string "firmware" (default) or "fs". Without mode, a filename containing "littlefs" is treated as a filesystem image.

Response

{ "status": "ok", "message": "Update successful. Rebooting..." }

System

POST /api/system/reboot

Reboot the device. Responds, then restarts about half a second later.

Response

{ "status": "ok", "message": "Rebooting..." }

Command Line Examples

Using curl from a terminal:

Get Status

curl http://tinklink.local/api/status

Scan for Networks

curl http://tinklink.local/api/wifi/scan

Connect to WiFi

curl -X POST http://tinklink.local/api/wifi/connect \ -d "ssid=MyNetwork&password=secret123"

Get Triggers

curl http://tinklink.local/api/config/triggers

Update Triggers

curl -X POST http://tinklink.local/api/config/triggers \ --data-urlencode 'triggers=[{"input":1,"profile":1,"mode":"SVS","name":"NES"},{"input":2,"profile":2,"mode":"SVS","name":"SNES"}]'

Set RetroTINK Baud Rate

curl -X POST http://tinklink.local/api/config/tink -d "baudRate=115200"

Send RetroTINK Command

curl -X POST http://tinklink.local/api/tink/send \ --data-urlencode "command=SVS NEW INPUT=1"

Send Switcher Command

curl -X POST http://tinklink.local/api/switcher/send -d "message=1!"

Discover AVR Receivers

curl http://tinklink.local/api/avr/discover

Configure AVR

curl -X POST http://tinklink.local/api/config/avr \ -d "enabled=1&ip=192.168.1.50&input=GAME"

Send AVR Command

curl -X POST http://tinklink.local/api/avr/send -d "command=PW?"

Set LED Color

curl -X POST http://tinklink.local/api/debug/led -d "color=blue"

Get Logs

curl "http://tinklink.local/api/logs?count=20"

Upload Firmware via OTA

curl -X POST http://tinklink.local/api/ota/upload \ -F "mode=firmware" -F "file=@firmware.bin"

Backup Config

curl http://tinklink.local/api/config/backup -o config_backup.json

Restore Config

curl -X POST http://tinklink.local/api/config/restore \ -H "Content-Type: application/json" -d @config_backup.json

Reboot Device

curl -X POST http://tinklink.local/api/system/reboot
